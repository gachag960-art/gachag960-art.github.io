I run eight Claude Code sessions at once, each with its own job.

I build a game and a chat app on my own. To do that, I split Claude Code into sessions by area. One commander session assigns work and audits the results; the others commit and report every time they finish a task. Claude drops earlier decisions when a conversation gets compacted, so I also wrote a memory tool that pulls my own words back out of the raw transcripts.

Memory that survives compaction

The ledger and the memory files are written by Claude compressing things into one line. What got lost was always lost in that compression.

So I wrote a Node.js tool that goes back to the uncompressed transcripts and pulls out what I actually said, each time it is needed. The idea is borrowed from the Just-in-Time Memory paper (arXiv 2609.27334). Every time I type a message, an entry hook adds the matching ledger lines and up to two of my past messages that match strongly. It takes about one second. When the commander hands work to a crew session, Haiku writes paraphrases to widen the search and picks the matches; that takes about a minute.

To measure it, I took 12 past rulings, asked about each one in different wording from the original, and counted how often my original message landed in the top 5.
